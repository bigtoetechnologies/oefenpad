The five word-type families plus Werkwoorden hold 871 distinct lemmas (research count of 20 November, before the last few promotions): 405 verbs, 249 nouns, 153 adjectives, 65 adverbs. Only "arm" sits in two families. The master list has 10,000 lemmas, so most words have no card yet.

How the families work

One card per item with a picture brief: scene, the one mark that must read, near misses, Dutch alt text, and for most families a contrast partner and an example sentence. Items are taught in contrast sets of two or three that differ in exactly one visible element.

  • The six newer families: edit the source files under tools/_xx_tmp/, rebuild with the family builder, then run the family checker until it reports 0 errors. Rerunning a builder overwrites every page of that family.
  • Voorzetselpaden: the band pages are the master. Read Docs/voorzetselpaden/AGENTS.html first. Never Read those pages whole: they embed base64 images. Use tools/prepositions-pages.py or Python re with the base64 masked.
  • Menus and index: python3 tools/wire-card-families-nav.py rewires the nav of every doc page and the card grid on Docs/index.html from the real pages and counts. It is safe to rerun.
  • Tests: dotnet test server/Oefenpad.Tests (44 tests). Port 8080 belongs to the owner; the account server uses 8098.

Quality controls and their limit

Each checker is mechanical: ids, fields, partners, alt-text stems, banned imagery, band rules, cited lexicon facts and cross-family duplicates. None of them judges Dutch. Every Dutch sentence, form and gloss was checked only by AI reviewers, never by a native speaker. The owner will go through the native-check list on their own machine (~/claude-scratch/native_check_list_2026-11-20.md, 42 items, outside the repo).

The working pattern that found real errors: author, then a strict checker, then an independent review, then a fix pass. The first review round found 268 problems that the checkers had missed, and the B1/B2 round found 168 more.

Explanation cards

Explanation cards teach every verb that has no honest single drawing, so no verb is skipped. Each is a picture, a short Dutch scene and one ja/nee question, with four examples per sense. The rules are in Docs/decisions.html; the cards are in Explanation cards. The Werkwoorden pages link every SKIP verb to its card. No game uses the cards yet.

ReviewThree AI rounds: author, then an independent opus review of every card, then fixes. The reviews changed several thousand fields and corrected a handful of wrong ja/nee answers. No native speaker has read any of it.

The method that worked for the 779 verbs: a list file per batch of about 22 verbs under tools/_ex_tmp/, one author agent per batch following tools/_ex_tmp/BRIEF.md, an independent review of every file, then build-explanation-cards.py, wire-card-families-nav.py and build-verb-cards.py. Separable verbs need their own brief first, because the existing Scheidbare cards use a different format. Run the author and reviewer agents in parallel, each owning its own JSON file.

Pitfalls for the next session

  • tools/build-adjective-cards.py reads the CSS = """ constant out of tools/build-verb-cards.py. Keep that constant intact.
  • The lexicon files are row-aligned to woorden.tsv (10,001 lines with the header). Never add, delete or reorder rows. tools/build-verb-forms.py now only appends rows for carded verbs; never let it overwrite.
  • The lexicon files list some lemmas with a suffix (zijn (verb), laag (adj)) and some homographs under suffixed keys. Look up both forms.
  • aan-boord (Bijwoorden) must keep that id: Vaste uitdrukkingen aan-wal cross-references it.
  • Parallel agents on the same repo work if each owns its own files; two edits to one file do not. Give every agent an explicit file list and forbid nav and index edits, then wire once at the end.
  • CLAUDE.md has an uncommitted word-list note from the owner. Do not commit it for them.
